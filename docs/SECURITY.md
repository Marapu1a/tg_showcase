# Валидация и ограничения локального пилота

Проверено 29 октября 2026 года. Это описание реализованных проверок, а не обещание защиты от любой атаки.

## Формы и сервер

| Поле / ресурс       | Ограничение                                                     |
| ------------------- | --------------------------------------------------------------- |
| Название            | 100 символов                                                    |
| Описание            | 700 символов                                                    |
| Комментарий заявки  | 500 символов                                                    |
| Цена                | 0,01–999 999,99 ₽, максимум 2 десятичных знака                  |
| Количество товара   | 1–100 000 или без ограничения                                   |
| Количество в заявке | 1–99, не больше остатка и предела суммы в БД                    |
| Telegram            | @, латинская буква в начале, буквы/цифры/\_, 4–32 знака после @ |
| Телефон             | 7–15 цифр; пробелы, + в начале, скобки и дефисы допускаются     |
| Другой контакт      | 160 символов, хранится и показывается текстом                   |
| Фото                | JPEG/PNG/WebP, до 4 MiB, до 25 млн пикселей, без анимации       |
| Обработанное фото   | JPEG до 1600 пикселей и 1 MiB, без исходных метаданных          |
| Декодирование фото  | Не более 2 одновременно в одном процессе                        |
| Данные продавца     | До 200 товаров (включая архив) и 200 загруженных фото           |
| Обычный HTTP body   | 16 KiB; для фото отдельный лимит 5 700 100 байт с учётом base64 |

Ошибки показываются рядом с полями, неверный итог не вычисляется. Отправка выключена при неверных данных или выполняющемся запросе. Повторное нажатие дополнительно блокируется синхронно. Есть счётчики символов, заметные disabled/error/focus-состояния. Статусы заказов обозначены текстом и цветом.

Сервер независимо проверяет входные данные. Телефон нормализуется, Telegram-контакт приводится к нижнему регистру. Проверка формата не подтверждает принадлежность контакта покупателю.

## Частота запросов

- Для маршрутов без специального лимита: 120 запросов в минуту на адрес клиента.
- Маршруты изменения данных: 20 в минуту на адрес и маршрут; переходы «Купить»/«Подробнее» также ограничены 20.
- Фото: 5 загрузок в минуту на адрес и маршрут.
- Дополнительно на авторизованного продавца: 90 чтений, 30 изменений и 5 фото в минуту, независимо от смены IP.
- До 5 новых заявок на контакт и публикацию за 10 минут, проверяется в транзакции БД.
- Бот обрабатывает не более одного обновления от пользователя за 2 секунды и 10 обновлений суммарно в секунду.

Лимиты HTTP и бота находятся в памяти процесса; перезапуск их сбрасывает. Для нескольких серверов нужен общий limiter. Лимиты не заменяют защиту от распределённых атак, мониторинг и ограничения на уровне инфраструктуры. В частности, гостевой покупатель с меняющимися адресами/контактами остаётся риском для доступности остатков.

За локальным cloudflared все соединения приходят с loopback. TRUST_LOCAL_CLOUDFLARE=1 позволяет использовать CF-Connecting-IP только с loopback-соединения и только при привязке API к loopback. По умолчанию флаг выключен, произвольные proxy-заголовки не используются. Нельзя включать этот режим за другим прокси, передающим заголовок клиента без проверки.

## Повторы и доступ

Заявка и резерв записываются атомарно в serializable-транзакции. UUID и отпечаток данных защищают от дубля; UUID нормализуется по регистру. Другие данные с тем же ключом дают конфликт. Отмена возвращает остаток один раз. Цена и название заказа — снимок; изменение товара не меняет историю.

При потере ответа браузер хранит ключ и исходные данные незавершённой отправки в sessionStorage текущей вкладки. Поля блокируются, повтор использует те же данные. Это относится к созданию заявки и товара. После подтверждения временный запрос удаляется. Данные не записываются в постоянное localStorage. Закрытие вкладки удаляет возможность автоматического восстановления через эту вкладку; перед новой заявкой стоит свериться с продавцом.

Приватные маршруты проверяют подпись Telegram и владельца. Фото для товара должно принадлежать продавцу. Устаревшие POST /products, /products/:id/images, /offers и POST /click/\* возвращают 410: создание идёт через /listings, фотографии — через /listings/photo. Старые маршруты редактирования ограничены по длинам и количеству, старые списки — максимум 100 записей; актуальные списки имеют пагинацию.

Публикация имеет блокировку от одновременной отправки. При неизвестном результате повтор запрещён до проверки канала. Старые уже опубликованные сообщения не менялись.

## Меню бота

/start убирает старую reply-клавиатуру с неработающими адресами и показывает актуальные inline-кнопки. Доступны канал, товары, заказы и добавление товара. Статистика и оплата сервиса не предлагаются как готовые функции.

Старые сообщения с inline-ссылками остаются историческими; временный туннель может сменить адрес. Для пилота с реальными продавцами нужен постоянный домен.

## Проверки и оставшиеся ограничения

11 автоматических тестов, включая реальную отдельную схему PostgreSQL: конкурентные заявки, дубль ключа и конфликт данных, остаток, однократная отмена, чужие данные/фото, квоты, ограничения HTTP, телефоны и строки со скриншотов, обновление клавиатуры бота без реальных сообщений.

Браузерная проверка: неверные поля и выключенная отправка; сервер сохраняет товар/заявку, ответ искусственно теряется; перезагрузка и повтор возвращают единственную запись и единственный резерв. Проверены мобильная ширина, путь обработки заказа и отсутствие JS-ошибок. Telegram в тестах заменён.

Не входят в этот пакет: CAPTCHA/подтверждение гостевых контактов, общий limiter для нескольких процессов, очистка неиспользуемых фото, автоматическое истечение резервов, управление квотами в интерфейсе, производственная нагрузочная проверка, мониторинг, резервное копирование и правовые документы. Фото, которые были загружены и убраны из формы, тоже занимают квоту; они не удаляются автоматически, чтобы не затронуть используемые изображения.
