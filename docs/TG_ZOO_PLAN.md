# TG Zoo: хаб и панель владельца

Предложение от 01.11.2026. Объём первой версии админки уточняется у владельца.

## Публичная часть

- `tg-zoo.qianqi.site/` — компактный каталог Telegram-проектов.
- Первый проект — **PocketShowcase**, действующий бот `@showcase_lite_bot`.
- Карточка: название, короткое описание, состояние доступности, кнопка открытия.
- Страница проекта `/projects/pocketshowcase` с описанием и переходом в Telegram.
- Новые проекты добавляются в каталог через закрытую панель. Это метаданные
  и ссылки, не автоматическая установка произвольных приложений на сервер.

При запуске действующей Main Mini App без start_param оставляем вход в её
рабочий интерфейс, а не каталог. Старые ссылки `/offers/:id` и параметры
`buy_`, `detail_`, `offer_` продолжают работать. Новый маршрут `admin`
может открывать панель из бота, но сам параметр не даёт права доступа.

## Панель владельца

`/admin`, проверка подписанного Telegram initData и отдельного серверного
списка Telegram ID администраторов. Исключение из биллинга не является
административным правом. Начальный администратор — 1958826421.
Все административные API защищаются на сервере, скрытого URL недостаточно.

Первая версия:

1. Сводка PocketShowcase: аккаунты продавцов, подключённые каналы, товары,
   успешные публикации и заявки, разбивка по статусам и периоду.
2. Оплаты: получено Stars, возвращено, ожидает возврата, история операций.
   Отдельно реальный баланс бота из Telegram с временем обновления.
   При ошибке Telegram показывать недоступность, а не подставлять ноль.
3. Проблемы: неопределённые публикации, ожидающие возвраты, недоставленные
   уведомления. Показатели отражают фактическое состояние очередей.
4. Каталог: добавить/изменить/скрыть карточку проекта. Журнал изменений.

Не смешивать валюты товаров в одну денежную сумму. Заказ — заявка,
`DONE` — отметка продавца; сервис не подтверждает выручку от товаров.
В общую статистику не выводить контакты покупателей без конкретной задачи.

Блокировка продавцов, ручные возвраты, массовые операции и автоматизация
требуют отдельного определения правил. Не добавлять произвольное выполнение
команд на сервере, хранение новых токенов через форму или конструктор интеграций.

## Stars

Платёж за размещение поступает боту, создавшему счёт, — сейчас
`@showcase_lite_bot`. Баланс бота отдельный от личного баланса владельца.
По мере появления других ботов у них будут отдельные балансы; хаб показывает
сводку, но не объединяет средства автоматически.

Документация: https://core.telegram.org/bots/api#getmystarbalance,
https://core.telegram.org/bots/api#getstartransactions,
https://core.telegram.org/api/stars.

01.11.2026 выполнено read-only обращение `getMyStarBalance`: 0 Stars.
Это моментальный снимок, не постоянная настройка и не подтверждение
прохождения тестовой оплаты.

## Порядок реализации

Сначала каталог и совместимая маршрутизация, затем серверная авторизация
владельца, сводка/платежи/проблемы и редактирование каталога. Проверить запрет
доступа обычному продавцу, чужие ID, действующие ссылки покупателя и независимость
биллинга от админских прав. Деплой через отдельный release с сохранением данных.


## Эксплуатация первой версии

- В backend.env задаётся `OWNER_TELEGRAM_IDS=1958826421`. Пустое значение закрывает
  доступ всем. Billing exemption не даёт административных прав.
- Вход: `/admin` в боте либо `https://t.me/showcase_lite_bot?startapp=admin`.
  Открытие `/admin` в обычном браузере предлагает перейти в Telegram.
- API `/admin/*` требует подписанный Telegram initData и ID из allowlist.
  `/owner-access` сообщает текущему пользователю только его собственное право.
- Публичные `/projects` и `/projects/:slug` возвращают только видимые карточки.
  Скрытие или статус карточки не останавливают сам сервис.
- Изменения карточек фиксируются в OwnerAudit в одной транзакции; версия защищает
  от потери одновременных правок. Повторное создание с тем же slug возвращает 409.
- Статистика 7/30 дней скользящая; заявки сгруппированы по текущему статусу.
  Платежи выбираются по дате получения; возвраты относятся к этим же платежам.
  Список оплат — по 30 записей. Баланс Telegram кешируется на 60 секунд.
- Проблемы: UNCERTAIN, отправки старше пяти минут, ожидающие возврата платежи,
  неудачные или задержанные уведомления. Это состояние очередей в БД, не полный
  мониторинг сервера. Повторные отправки и возвраты выполняют существующие workers.
- Каталог допускает до 100 проектов и ссылки https://t.me/username. Подключение
  метрик другого бота потребует отдельной интеграции; добавление карточки её не создаёт.
- Миграция 20261101000100_hub_owner добавляет две таблицы и карточку PocketShowcase;
  существующие товары, заказы и платежи не меняет.

Проверки: RUN_DB_TESTS=1, STARS_BILLING_ENABLED=0 и backend test (каждый billing-тест
сам включает нужный режим). Изолированные схемы БД, Telegram замокан. Проверяются
границы доступа, скрытые карточки, вредоносные URL, конкурентное редактирование,
аудит, периоды, страницы оплат, проблемы, кеш и отказ получения баланса.
