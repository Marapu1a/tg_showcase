- Пользователь ОС: `tg-showcase`. Node 22, pnpm 10.33.0 установлен отдельно
  в `/opt/tg-showcase/tools`, без замены окружения других проектов.
- API: `127.0.0.1:4230`, Nginx отдаёт его через `/api/`.
- PostgreSQL: отдельные роль и база `tg_showcase` в существующем кластере
  на порту 5434. Пароль — только в `/etc/tg-showcase/backend.env`.
- Секреты бота: `/etc/tg-showcase/bot.env`, права 600.
- Очередь платёжных событий: `/var/lib/tg-showcase/payment-events`.
- Службы: `tg-showcase-api`, `tg-showcase-bot`.
- Nginx: `/etc/nginx/sites-available/tg-zoo`; шаблон в `infra/nginx/tg-zoo.conf`.
- TLS: Let's Encrypt, автоматическое продление Certbot. При продлении требуется
  reload Nginx; проверить deploy hook на сервере.

Nginx перезаписывает `X-Real-IP`; API доверяет ему только от loopback при
`TRUST_LOCAL_PROXY=1`. Внутренний путь `/api/internal/` снаружи закрыт.
Фото хранятся в PostgreSQL. Frontend собран с
`VITE_API_URL=https://tg-zoo.qianqi.site/api`.

## Резервные копии

`tg-showcase-backup.timer` запускает `infra/backup.sh` ежедневно в 03:30 UTC.
В `/var/backups/tg-showcase` сохраняются custom dump и очередь событий,
хранение 14 дней, права закрыты. Первое восстановление проверено в отдельной
временной БД: все 10 миграций восстановились, заказов 5 после переноса.
Копии на том же сервере не защищают от потери всего сервера: автоматическое
внешнее хранилище ещё не подключено.

## Обновление и откат

Сначала тесты, сборка frontend с production API, архив без `.env`, `.runtime`,
`node_modules`. На сервере распаковать новый release; `pnpm install --frozen-lockfile`,
`prisma generate`; сделать backup, применить миграции. Только затем переключить
`current` и перезапустить две службы. Предыдущую версию сохранить.
Откат кода — вернуть `current`; совместимость схемы проверить отдельно,
базу из backup автоматически не откатывать: можно потерять новые заказы.

Проверки: HTTPS `/`, `/terms`, `/privacy`, `/api/health`; запрет `/api/internal/`;
вход продавца и реальный платёж/возврат проверяются после переключения.
