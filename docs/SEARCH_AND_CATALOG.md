# Поиск, компактные списки и состояние продаж

Пакет от 29 октября 2026 года.

## Заказы

Вместо больших карточек — строки с номером, покупателем/контактом, товаром, количеством, суммой, датой и статусом. По нажатию открываются подробности и действия над заказом.

Поиск срабатывает после 250 мс без ввода. Предыдущий HTTP-запрос отменяется; его запоздавший ответ не меняет новые результаты. Во время поиска старые строки скрываются. При начале ввода включается «Вся история», после чего можно уточнить статус. Поиск ограничен 100 символами.

Поля поиска: номер заказа (можно с #), сохранённое имя, контакт Telegram, телефон и название товара на момент заказа. Регистр не важен, @ можно опустить, пробелы/скобки/дефисы в телефоне не мешают. Страна телефона автоматически не угадывается: 8 и +7 не считаются эквивалентными префиксами. Символы % и \_ ищутся буквально.

Фильтры: статус, товар, начальная и конечная даты. Даты включают полный календарный день по Москве. Список выдаётся по 30 записей, с переходами «Назад / Далее»; изменение фильтра возвращает первую страницу. Фильтры сохраняются в URL, значение поисковой строки не пишется в серверный журнал запросов.

«Заказы с этим контактом» открывает записи с тем же нормализованным контактом и способом связи. Это не глобальная карточка человека: одинаковое имя не объединяет людей, а другой контакт того же человека автоматически не угадывается.

## Изоляция продавцов

В каждом запросе списка, количества результатов, счётчиков, подробностей и перечня товаров используется ownerUserId из проверенного Telegram-входа. Присланный клиентом ownerUserId не используется. Источник для «Заказы с этим контактом» сначала проверяется на принадлежность продавцу. Чужой заказ или товар по прямому ID недоступен.

Один и тот же покупатель может покупать у разных продавцов. Каждый продавец видит только свои заказы — включая поиск по совпадающему имени, контакту и номеру, пагинацию и подборку похожих заказов.

Контакт в заказе остаётся снимком на момент оформления. Поиск не запрашивает актуальный Telegram-профиль покупателя. При смене покупателем username пригодится номер заказа или прежний контакт.

## Товары и публикации

Список показывает миниатюру, название, цену, состояние и доступный остаток. Полное фото, описание и действия открываются по нажатию. Поиск работает по названию товара/публикации; при начале поиска включаются все состояния, включая архив. По умолчанию архив скрыт.

| Состояние | Действия                                                                |
| --------- | ----------------------------------------------------------------------- |
| Черновик  | Опубликовать или убрать в архив                                         |
| В продаже | Приостановить или убрать в архив                                        |
| На паузе  | Возобновить или убрать в архив                                          |
| Архив     | Восстановить: опубликованный товар в паузу, неопубликованный в черновик |

Нет в наличии — признак нулевого остатка, а не отдельный ручной статус. Возобновить можно и при нулевом остатке, но форма заказа останется недоступна. Изменение количества и редактирование товара пока не добавлены.

Пауза не меняет существующие заказы и остаток. Возобновление использует прежний ID карточки, не отправляет новый пост и не переписывает сообщение в Telegram. Архивирование сохраняет всю историю. По ссылке опубликованного товара покупатель видит «Приём заказов временно приостановлен» или «Продажа завершена»; форма создания заявки выключена. Неопубликованные черновики в публичном API недоступны, в том числе после архивирования.

Все изменения состояния проверяют владельца и ожидаемый статус в транзакции. Повтор уже выполненного действия безопасен. Во время отправки поста или при неизвестном результате публикации изменения блокируются. Устаревший PATCH /offers/:id больше не позволяет менять status в обход этих проверок; DELETE использует безопасное архивирование.

Ссылки старых постов с выключенным временным туннелем не оживают от смены статуса: для стабильных ссылок нужен постоянный домен.

## API и проверка

- GET /orders: q, scope, productId, from, to, relatedTo, before. Возвращает компактные строки, total, next и счётчики собственных заказов.
- GET /orders/:id: подробности своего заказа.
- GET /orders/products: собственные товары для фильтра.
- GET /listings: q, scope, before; компактный список, total и next.
- GET /listings/:id: подробности собственного товара/публикации.
- POST /listings/:id/state: action PAUSE/RESUME/ARCHIVE/RESTORE и expectedStatus.

Миграция добавляет PAUSED, отдельное поле нормализованного контакта для поиска и индексы списков по владельцу. Исходные контакты и история сохраняются.

Проверено на отдельной схеме PostgreSQL: 1500 заказов одного продавца и 40 другого с теми же покупателями; отсутствие смешения результатов, счётчиков и подробностей, поиск по контакту/имени/номеру, буквальные спецсимволы, даты, пагинация и переходы состояний. В браузере проверены быстрый ввод с задержанным старым ответом, страницы, компактный мобильный интерфейс и пауза/возобновление/архив/восстановление. Тесты не публикуют реальные посты и не отправляют сообщения.

Добавлены история смены статусов, причины отмены и возврат всего заказа: [ORDER_WORKFLOW.md](ORDER_WORKFLOW.md). Отдельные обращения и частичные возвраты пока не добавлены. Текущий пакет не добавляет глобальную базу покупателей и не переносит деньги.
